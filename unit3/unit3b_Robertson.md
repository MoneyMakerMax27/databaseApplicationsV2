2. What a foreign key promises
b. In denormalized_demo.db, games.home_team_id is a foreign key to teams.team_id. If someone tries to insert a game with home_team_id = 99 and there is no team 99, what should the database do? What is that rule called?

Answer:
A database will refuse or reject the entry. this is called referential integrity

d. Pick either many-to-many row. Relational databases can't store a many-to-many directly. What table do you add, and what columns does it need?

Answer:
To resolve a many-to-many relationship, you add a junction table (such as Movie_Cast) with a primary key and foreign key columns referencing the primary keys of both connected tables (like movie_id and actor_id).

e. Not every database uses tables and keys. In a graph database (like the one behind Instagram's follow list), the same "who follows whom" relationship is stored as what two things? In a key-value store, how is a relationship handled?

Answer:
In a graph database, relationships are stored as nodes and edges, while in a key-value store, relationships are handled by storing one key inside another value, requiring the application to perform a second lookup.

Closing 3b — Vocabulary
TermYour definitionEntityA real-world person, place, thing, or event that you want to store information about in a database (becomes a table).AttributeA single piece of information or characteristic describing an entity (becomes a column).Natural keyA primary key that uses an existing real-world value that is already unique, like a Social Security number or email address.Surrogate keyA unique primary key generated by the database, such as an auto-incrementing ID number, that has no external meaning.Composite keyA primary key made by combining two or more columns together to uniquely identify a single row.Referential integrityA database rule ensuring that foreign key values always match a valid, existing primary key in the connected table.Junction tableA bridge table created specifically to break a many-to-many relationship into two one-to-many relationships.CardinalityThe measure of how many records in one table can relate to records in another table (such as one-to-one, one-to-many, or many-to-many).
